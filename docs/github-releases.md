# GitHub release updates

The release baseline starts at Alpha v.36 (`alpha-v36`). Do not backfill older builds.

After each completed full update, publish a new GitHub prerelease with the matching version, build notes, PKG, exFAT image, game-folder ZIP, corresponding source archives, checksums and testing instructions. Keep previous releases and their assets unchanged. Never replace published binaries in place.

Tag the exact commit used to build the binaries, even when later documentation changes exist on main. Public alpha publication was authorized on 18 November 2026. Preserve the chosen visibility unless explicitly directed otherwise. GitHub has no link-only access mode; a private repository requires collaborator invitations. Download published assets again, verify their checksums and validate the downloaded game-folder ZIP before reporting completion. Describe hardware checks and remaining limitations accurately.

Do not upload user profiles, saved scores, logs, console addresses, credentials, downloaded/custom songs or private test captures. Retain the approved original PC bundled songs and required notices/source. Use the isolated release source repository; do not broadly commit the development workspace.

Repository prose should use a direct project voice. Describe the software, installation and test results without conversational acknowledgements or references to the maintainer as a third party.

On 18 November 2026 the release policy changed at the project owner's request: after publishing and verifying Alpha v.39, older releases are kept as drafts, leaving only the current release publicly downloadable. Preserve their files and source tags. Publish the new release before deploying its exact artifacts to the base PS5 and Pro. The application remains labelled as an Alpha/work-in-progress test build even when GitHub marks it Latest.

Alpha v.39 received an explicitly requested same-version visual refresh for subdued white six-fret open notes. For this exception, refresh the binaries, matching source tag and all checksums together, retain the prior artifact set locally, verify the new downloads, then deploy that exact build. Future updates keep the normal version-bump policy unless directed otherwise.
